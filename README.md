# Simulated Input（模拟输入）

一个基于 Chrome 的浏览器扩展：把一段文本一键“分发”到你预先配置好的页面元素上。

例如：平时反复要在某个后台的搜索框、备注框里粘贴同一段内容，配置一次之后，以后只要点扩展图标 → 点一下配置名称按钮即可填入。

- **Manifest V3**
- 纯原生 HTML + JavaScript，无构建步骤、无第三方依赖
- 配置保存在浏览器本地（`chrome.storage.local`），不上传任何数据

## 功能特性

- **多目标配置**：可以配置任意多组“目标”，每组包含名称、目标元素选择器、可选的 iframe 选择器，以及一段默认内容。
- **一键发送**：打开扩展面板，每个配置就是一个按钮（**按钮文字即配置名称**），点击即发送，不再需要额外的“发送”按钮。
- **临时内容覆盖**：面板顶部的输入框可以临时输入一段文本，发送时优先使用它；留空则使用该配置里保存的「输入内容」。
- **按钮智能置灰**：打开面板时会检测当前页面是否存在对应的目标元素，找不到就把该按钮置灰并禁用（避免误点）。
- **受限页面友好提示**：在浏览器内部页面（`chrome://` 等）上打开面板时，会直接提示原因并把所有按钮置灰，而不是静默失败。

## 安装

本扩展未上架应用商店，通过“加载已解压的扩展程序”安装：

1. 在地址栏输入 `chrome://extensions` 并回车。
2. 打开右上角的 **开发者模式** 开关。
3. 点击左上角的 **加载已解压的扩展程序**。
4. 选择本项目所在的文件夹（即包含 `manifest.json` 的那一层目录，`web-simulate-input/`）。
5. 加载成功后，点击工具栏的拼图图标 🧩，把 **Simulated Input** 固定到工具栏，方便日常使用。

> 要求浏览器支持 Manifest V3，即 Chrome 88 及以上（Edge、Brave 等 Chromium 内核浏览器同理）。

> **修改代码后必须重新加载扩展**：回到 `chrome://extensions`，在 Simulated Input 卡片上点一下刷新按钮 ⟳。否则运行的仍是旧代码。

## 快速上手

1. **打开选项页**：在 `chrome://extensions` 里找到 Simulated Input，点 **扩展程序选项**；或者右键工具栏图标 → **选项**。
2. **新增配置**：点 **新增配置**，在弹窗里输入一个名称（例如“搜索框”），确定后会新增一个配置组。
3. **填写配置**：
   - **目标选择器**：目标元素的 CSS 选择器，例如 `#kw`、`input[name=“q”]`
   - **iframe 选择器**：仅当目标元素位于 iframe 内部时才填，例如 `iframe#main`；否则留空
   - **输入内容**：面板输入框留空时使用的默认文本
4. **保存配置**：点 **保存配置**，看到绿色提示“配置已成功保存”即成功。
5. **使用**：切换到目标网页 → 点扩展图标 → 点击对应的配置名称按钮，内容就被填入目标元素了。

## 界面说明

### 扩展面板（Popup）

```
┌─────────────────────────────────┐
│ 请输入要发送的文本              │  ← 临时输入框（textInput）：留空则用配置里的「输入内容」
│                                 │
│ 提示条（仅异常或无配置时出现）  │  ← notice
│                                 │
│ [ 搜索框 ]                      │  ← 按钮文字即配置名称，点击即发送
│ [ 备注 ]                        │
└─────────────────────────────────┘
```

- **配置名称按钮**：面板里不再有单独的“发送”按钮，按钮上直接显示配置名称，**点击按钮即执行发送**。鼠标悬停时按钮颜色加深，并会提示这条配置要发送到哪个元素。
- **临时输入框**：输入内容后点任意一个配置名称按钮，都会发送这里的文本（优先级高于配置内容）。每次发送后不会自动清空。
- **提示条**：出现以下情况时显示，正常使用时隐藏。
  - 当前页面不可注入（`chrome://` 等）
  - 还没有配置任何目标
- **置灰的按钮**：按钮变为灰底灰字（鼠标显示 `not-allowed`），表示当前页面**用不了**这个目标，原因见 [已知限制](#已知限制)。
  - 置灰的按钮**真的点不动**：鼠标点击被 CSS 与发送逻辑双重拦截，键盘（Tab 聚焦后按 Enter / Space）也无效 —— 因为它是用原生 `disabled` 的按钮实现的，同时移出了 Tab 焦点顺序。
  - **鼠标悬停在置灰的按钮上会显示具体原因**，例如“当前页面未找到 本页面的「#kw」”、“当前页面未找到 iframe「iframe#ed」内的「body.editor」”，可据此判断是选择器写错了、还是页面不对。置灰状态在**每次打开面板时**重新检测。

### 选项页（Options）

在独立标签页中打开，包含三个按钮：

| 按钮 | 作用 |
| --- | --- |
| **新增配置** | 弹窗输入名称后，在页面下方追加一个空配置组 |
| **保存配置** | 把当前页面上**所有**配置组写入本地存储（覆盖式保存） |
| **清除配置** | 清空本地存储中的全部配置 |

- 每个配置组就是一个“目标”，包含配置名称 + 三个字段。
- 保存/清除的结果会在按钮下方显示提示（绿色成功 / 红色失败），2 秒后自动隐藏。
- **新增或修改后一定要点「保存配置」**，否则关闭页面即丢失。

## 配置项说明

| 字段 | 是否必填 | 说明 | 示例 |
| --- | --- | --- | --- |
| **配置名称** | 是 | 仅用于在面板上显示，方便识别。通过「新增配置」时的弹窗输入，之后不可改（想改就删掉重建） | `搜索框` |
| **目标选择器** | 是 | 目标元素的 CSS 选择器，交给 `document.querySelector()` 解析；**只作用于第一个匹配到的元素** | `#kw`、`input[name=“q”]` |
| **iframe 选择器** | 否 | 目标元素所在 iframe 的选择器；**留空表示目标元素在主文档中** | `iframe#editor` |
| **输入内容** | 否 | 面板输入框留空时，发送的默认文本 | `你好，世界` |

> 保存时所有字段都会做 **trim**（去掉首尾空白）。

配置最终以如下结构存于 `chrome.storage.local` 的 `configs` 键下：

```json
{
  "configs": [
    {
      "label": "搜索框",
      "target_selector": "#kw",
      "iframe_selector": "",
      "content": "你好，世界"
    }
  ]
}
```

## 选择器写法与示例

目标选择器就是标准的 CSS 选择器，下面是一些常用写法：

| 场景 | 写法 |
| --- | --- |
| 按 id | `#username` |
| 按 class | `.search-input` |
| 按属性 | `input[name=“q”]`、`textarea[placeholder*=“备注”]` |
| 按层级 | `form#login > input:nth-of-type(2)` |
| 按文本附近的结构 | `.modal-body textarea`（CSS 无法按文本内容匹配） |
| iframe 选择器 | `iframe#main`、`iframe[src*=“editor”]`、`iframe.editor-frame` |

**如何快速拿到选择器**：在目标网页上右键目标元素 → **检查**，在 Elements 面板里右键该元素 → **Copy** → **Copy selector**，粘贴到配置里即可（可按需简化）。

## 典型使用场景

### 场景一：向普通页面的输入框发送文本

| 字段 | 值 |
| --- | --- |
| 配置名称 | 搜索框 |
| 目标选择器 | `#kw` |
| iframe 选择器 | （留空） |
| 输入内容 | 模拟输入测试 |

打开目标网页 → 点扩展图标 → 点击面板里文字为「搜索框」的按钮。

### 场景二：目标元素在 iframe 内部

某些富文本编辑器、内嵌表单会把 `input` / `textarea` 放在 iframe 里，此时主文档的 `document.querySelector` 找不到它，需要额外指定 iframe：

| 字段 | 值 |
| --- | --- |
| 配置名称 | 编辑器正文 |
| 目标选择器 | `body.editor` |
| iframe 选择器 | `iframe#editor` |
| 输入内容 | 这是一段测试文本 |

查找顺序是：先在主文档里找 iframe → 进入该 iframe 的文档 → 在其中找目标元素。

> ⚠️ **iframe 必须与主页面同源**，否则浏览器禁止访问其内部文档，该按钮会置灰。

### 场景三：临时发送一段不同的内容

不需要改配置：直接在面板顶部的输入框里输入内容，再点任意一个配置名称按钮。输入框有内容时，点哪个按钮都是发送这段临时文本。

## 工作原理

```
┌─────────────┐   读/写 configs    ┌──────────────────────┐
│  选项页      │ ─────────────────▶ │ chrome.storage.local │
│ options.js  │ ◀───────────────── │   { configs: [...] } │
└─────────────┘                    └──────────────────────┘
                                              ▲ 读取配置
                                              │
┌─────────────┐   注入脚本到当前标签页   ┌─────────────┐
│  扩展面板    │ ─────────────────────▶ │  目标网页    │
│  popup.js   │ ◀───────────────────── │             │
└─────────────┘    返回检测结果/执行     └─────────────┘
```

1. **配置读写**：选项页把配置写入 `chrome.storage.local` 的 `configs` 数组；面板读取它并据此渲染出一行行配置名称按钮。
2. **打开面板时**：
   - 先执行 `chrome.scripting.executeScript` 注入 `injectFunctions`，在页面里挂上 `window.getTarget(config)`，用于“找元素”。
   - 再对每条配置调用 `checkTargetExists`，返回 `false` 就把对应按钮置灰并禁用。
3. **点击发送时**：注入 `sendText(inputText, config)`，在页面里通过 `window.getTarget` 找到元素，把文本写进去。

注入的函数都运行在页面的脚本环境中（`window.getTarget` 挂在页面窗口对象上），因此不会和扩展面板的代码互相污染。

## 权限说明

| 权限 | 用途 |
| --- | --- |
| `activeTab` | 你点击扩展图标时，临时获得**当前这一个标签页**的访问权，用于注入脚本。扩展不会常驻访问所有网站。 |
| `scripting` | 使用 `chrome.scripting.executeScript` 向页面注入查找/填写逻辑。 |
| `storage` | 把配置保存在浏览器本地 `chrome.storage.local` 中。 |

如需在本地 `file://` 页面（自己保存的 HTML）上使用，请在 `chrome://extensions` 的扩展详情页里额外打开 **允许访问文件网址**。

## 已知限制

1. **无法用于浏览器内部页面**
   `chrome://`（如 `chrome://extensions`、`chrome://newtab`）、`edge://`、`chrome-extension://`、`view-source:`、`devtools://`、`about:`，以及 Chrome 网上应用店页面，**Chrome 内核一律禁止扩展注入脚本**，这不是本扩展的缺陷，也无法绕过。

   在这类页面上打开面板时，会看到提示：
   > 当前页面无法使用：浏览器内部页面（chrome://…）不允许扩展注入脚本
   > 请切换到普通网页（http/https）后重新打开本面板。

   **常见触发场景**：刚在 `chrome://extensions` 重新加载完扩展，顺手在当前标签页点了图标。切到任意普通网页即可。

2. **是“直接赋值”，不是“真实按键”**
   当前实现是把文本直接写入元素的 `value` 属性，**不会派发 `input` / `change` 事件**。对于 React、Vue 等受控组件，可能出现“页面看起来填上了、但框架状态没更新、点提交还是空”的情况。
   （代码中已实现一个模拟逐字符按键的 `sendByOnceKey`，但尚未接入发送流程。）

3. **iframe 必须同源**
   跨域 iframe 的内部文档无法访问，会提示“无法访问 iframe 内容（可能跨域）”，该按钮置灰。

4. **只作用于第一个匹配元素**
   使用 `document.querySelector` 语义，选择器匹配到多个元素时只填第一个。

5. **没有删除单个配置的功能**
   只能点「清除配置」清空全部，然后重新添加。

6. **清除配置不会立即刷新界面**
   「清除配置」只清空本地存储，当前选项页上的配置组仍显示着。请手动刷新页面（F5）确认已清空。

7. **配置名称不可编辑**，需要改名时只能清空重建。

8. **不适用于富文本 / `contenteditable` 元素**
   这类元素没有 `value` 属性，直接赋值无效。

## 常见问题（FAQ）

**Q：面板里一个按钮都没有？**
A：说明还没有配置。面板会提示「还没有任何配置。请在扩展的选项页中添加目标选择器和要发送的内容。」，按提示前往选项页添加配置，并记得点「保存配置」。

**Q：某个按钮是灰的、点不动？**
A：这说明该目标在当前页面用不了，原因有二：① 当前页面不允许注入（浏览器内部页面）；② 当前页面里找不到该配置的选择器对应的元素。**把鼠标停在那一行上会直接显示原因**，照着改选择器或换到正确的网页即可。

**Q：置灰的按钮为什么不是直接隐藏？**
A：保留显示是为了让你知道"配置还在，只是当前页面用不上"，同时通过悬停提示直接告诉你缺的是哪个选择器。每打开一次面板都会重新检测一次。

**Q：点了发送没反应？**
A：先看这个按钮是不是置灰的（置灰状态下点击会被拦掉，不会发送）。如果按钮正常，再打开网页自身的开发者工具（F12 → Console）看报错：若看到「未找到 iframe 元素」，说明 iframe 选择器没匹配上；若看到「无法访问 iframe 内容（可能跨域）」，说明该 iframe 与主页面不同源；若看到「选择器不合法」或「未配置目标选择器」，说明配置里的选择器为空或语法有误；若没有任何报错但内容没进框架，通常是 [已知限制](#已知限制) 第 2、8 条描述的受控组件 / 富文本元素。

**Q：控制台报 `Cannot access a chrome:// URL`？**
A：当前标签页是浏览器内部页面，Chrome 禁止注入。切换到普通 http/https 网页即可，面板也会同步给出提示。

**Q：报 `Cannot read properties of undefined (reading 'forEach')`？**
A：这是旧版本的缺陷（首次安装尚无配置时读取配置失败），已在 `8f320eb` 修复。请在 `chrome://extensions` 重新加载扩展。

**Q：改了配置但面板没变化？**
A：面板每次打开都会重新读取配置，关闭再打开即可（不用刷新网页）。如果改的是代码，则需要在 `chrome://extensions` 重新加载扩展。

**Q：配置丢了？**
A：配置存在浏览器本地存储里，卸载扩展或清除浏览器数据都会导致其被清空。重要配置请自行备份（可在扩展详情页用开发者工具查看 `chrome.storage.local`）。

**Q：支持 Firefox 吗？**
A：未做适配与测试，建议使用 Chrome 及 Chromium 内核浏览器（Edge、Brave 等）。

## 开发与调试

本扩展无需构建，改完源码直接重新加载即可。

| 调试对象 | 方法 |
| --- | --- |
| 扩展的加载错误 / Service 错误 | `chrome://extensions` → 扩展卡片上的 **错误** 按钮 |
| 面板（popup） | 右键工具栏图标 → **检查弹出内容** |
| 选项页 | 它本身就是普通标签页，直接按 F12 |
| 注入到网页的代码 | 在**目标网页**按 F12 查看，日志打在网页自己的控制台里 |

关键入口：

- `popup.js` 的 `isRestrictedUrl()` —— 判断当前页面是否属于禁止注入的页面
- `popup.js` 的 `injectFunctions()` —— 注入到页面的“找元素”逻辑（`window.getTarget`）
- `popup.js` 的 `sendText()` / `checkTargetExists()` —— 注入到页面的“填写”与“检测”逻辑
- `options.js` —— 配置的增删改查与写入 `chrome.storage.local`
